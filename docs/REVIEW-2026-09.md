# MAERMIN — Full Project Review

**Scope:** `main` @ clone of 2026-09-30 · analysis only, no code changed · all findings verified in source unless marked *(unverified)*.
**Gates:** `npm run check` → ✅ 178 JS files pass · `npm test` → ✅ 76 suites, 2,206 assertions, 0 failures · `npm run build:web` → ✅ 94 local scripts → `dist/maermin.min.js` **1,000 KB minified / 287 KB gzip**, `dist/compute.worker.js` 13 KB.

> Brief corrections to the review brief: `renderer.js` is **5,346** lines (not ~3,800); `compute.worker.js` runs **only** Monte Carlo + correlation — XIRR/TWR, FIFO, backtests and German tax all run on the main thread.

## 1. Executive summary

1. **The Tax view shows a different number than the PDF/Excel it exports.** On-screen KPIs come from the legacy `calculateGermanTax` (no FX conversion, Sparerpauschbetrag applied to crypto, no Freigrenze, no Teilfreistellung/VAP); exports use `MaerminTaxReport`. Repro: same data → screen **50.11 €** tax, PDF **0.00 €** (§4 B1). *Critical.*
2. **Built-in broker CSV parsers corrupt German data.** Trade Republic "Verkauf" is booked as a **buy** (`'verkauf'.includes('kauf')`), dividends become **sells**, and `parseFloat('180,55') → 180` / `'1.234,56' → 1.234` for TR and DEGIRO. The wizard also ignores the chosen broker. *Critical.*
3. **Live price-history timestamps have no year** (`toLocaleString('en-US', …)` → `"09/30, 08:14 PM"`, parsed by V8 as **2001**). This silently breaks TWR, the Cashflow chart, the Vorabpauschale prefill (→ VAP = 0) and back-dated savings-plan pricing (→ today's price booked as "exact"). *High, one root cause.*
4. **XIRR mixes currencies**: cash flows use raw `quantity × price` in the transaction currency while the terminal value is EUR — any USD position biases XIRR. TWR is not a TWR (constant current quantities, lexicographic date sort). *High.*
5. **Monte Carlo ignores the portfolio**: positions carry no `currentValue`, so the start value is **cost basis** and μ/σ always default to **8 % / 18 %** — even for a 100 % crypto book. *High.*
6. **German-tax depth has correctness gaps**: Vorabpauschale counted in the value year instead of Y+1 (§18 (3) InvStG); month factor uses the *first ever* buy (Sparplan lots overstated); VAP credit not pro-rated on partial sales; **no Quellensteuer credit**; **Basiszins 2026 (3.20 %) missing**; ETFs and crypto land in the wrong loss pots in the tax advisor. *High.*
7. **Sync silently drops the other device's edits** for every non-transaction key (watchlist, savings plans, net-worth accounts …): the local snapshot is stamped `Date.now()` at merge time, so "last write wins" always picks local. *High.*
8. **At-rest encryption and sync cover only the pre-v10 keys.** Real assets, daily value snapshots, interest ledger, tags, rules, corporate actions, taxpayer name + **tax ID** stay plaintext in `localStorage` and never sync; the full backup is plaintext JSON. *High (privacy promise).*
9. **Seven independent FIFO implementations and two German tax engines** disagree on fees, FX and corporate actions (e.g. positions show avg cost 100 €, tax lots 102 €). This is the main maintainability risk and the source of several bugs above.
10. **Performance:** one 1 MB bundle + render-blocking jsPDF, an artificial ~1.1 s splash, no `React.memo` anywhere, overview metrics recomputed on every render, full `EURUSD=X range=max` download every session, histories refetched per view. Best ROI: lazy-load jsPDF, fix splash, memoise overview, shared IndexedDB history cache.

## 4. Bugs & logic issues (with reproductions)

All scripts run against the unmodified repo with `node` (they `require` the dual-exported modules).

**B1 — Tax view vs. export disagree (Critical)**
```js
const TE=require('./tax-calculation-engine.js'), TR=require('./tax-report-builder.js');
const S={abgeltungRate:.25,soli:true,kirchensteuer:0,freistellungsauftrag:1000,cryptoExemption:true};
const txs=[{type:'buy',category:'stocks',symbol:'AAPL',quantity:10,price:100,fees:10,currency:'USD',date:'2025-02-01'},
 {type:'sell',category:'stocks',symbol:'AAPL',quantity:10,price:150,currency:'USD',date:'2025-06-01'},
 {type:'buy',category:'crypto',symbol:'BTC',quantity:1,price:500,currency:'EUR',date:'2025-01-10'},
 {type:'sell',category:'crypto',symbol:'BTC',quantity:1,price:1200,currency:'EUR',date:'2025-03-10'}];
TE.calculateGermanTax(txs,2025,S).totalTax;                     // 50.11  (shown on screen)
TR.build(txs,{year:2025,exchangeRate:.9,germanTax:TE.GermanTax,taxSettings:S}).summary.germanDetail.totalTax; // 0 (PDF)
```
Expected: identical; correct is 0 (441 € capital gain < 1,000 € allowance; 700 € crypto < 1,000 € Freigrenze).

**B2 — Trade Republic / DEGIRO parsing (Critical)**
```js
const {BrokerParsers:B}=require('./import-export-engine.js');
B.tradeRepublic.parse([{Typ:'Verkauf',Wertpapier:'Apple','Stück':'2',Kurs:'180,55',Datum:'2025-03-01'}],[]); // type 'buy', price 180
B.degiro.parse([{Produkt:'VANGUARD FTSE AW',ISIN:'IE00BK5BQT80',Anzahl:'-3',Kurs:'1.234,56'}],[]);          // price 1.234
```
Test: expect `sell` / `180.55` / `1234.56`.

**B3 — Year-less price timestamps (High)**
`new Date("09/30, 08:14 PM")` → `2001-09-30` in V8. Consequences: `returns-engine.twr` → **−16.7 %** for a 100→120 move across New Year; VAP prefill gets identical start/end price → VAP 0 (`german-tax-view.js:30-43, 70-72`); `savings-plan-executor.priceAtDate` accepts any 2001 point as ≤ due date → back-dated plan buys priced at today's price and marked *not estimated* whenever the per-symbol series fetch failed (`savings-plan-executor.js:203-213`, `renderer.js:384`).
Test: `expect(R.twr({btc:[{timestamp:'12/30, 10:00 AM',price:100},{timestamp:'01/02, 10:00 AM',price:120}]},{crypto:[{symbol:'BTC',amount:1}]})).toBeCloseTo(0.2)` — fails today; fix = ISO timestamps + one-off migration of existing points.

**B4 — TWR with misaligned timestamps (High)**
BTC and AAPL both flat, points at 00:00 vs 14:30 UTC → `twr = −0.5` (`returns-engine.js:113-121`).

**B5 — XIRR currency mix (High)**
Buy 10 × 100 USD, rate 0.90, price unchanged → terminal value 900 € vs outflow −1,000 → XIRR ≈ −10 % p.a. instead of 0 %. Test after extracting `buildCashflows(transactions, portfolio, prices, fxAt)` from `features2.js:42-58`.

**B6 — Monte Carlo ignores market value and allocation (High)**
```js
const pf=require('./metrics.js').buildPositions([{type:'buy',category:'crypto',symbol:'BTC',quantity:1,price:10000,currency:'EUR',date:'2020-01-01'}],{exchangeRate:1});
require('./monte-carlo-engine.js').runMonteCarloSimulation(pf,{iterations:200,years:1});
// initialValue 10000 (cost), expectedReturn 0.08, volatility 0.18 — for 100 % crypto
```

**B7 — Notes-based income detection (High)**
A `buy` with `notes:'Dividend reinvestment'` (2 × 100 €) → `summary.dividendIncome = 200` (`tax-report-builder.js:150`). Same for `interest`.

**B8 — Fee-less position cost basis (High)**
`buildPositions([{type:'buy',…,quantity:10,price:100,fees:20}])` → `purchasePrice 100`; tax lot = 102.

**B9 — Sync loses remote edits (High)**
```js
const S=require('./sync-engine.js');
S.mergeSnapshots({updatedAt:Date.now(),data:{maermin_watchlist:'["NVDA"]'}},
                 {updatedAt:1000,     data:{maermin_watchlist:'["NVDA","MSFT"]'}}).merged.data.maermin_watchlist; // '["NVDA"]'
```
In `sync()` the local snapshot is always built "now" (`sync-engine.js:336`), so this is the normal path, not an edge case.

**B10 — Vorabpauschale timing & Sparplan month factor (High)**
Fund held since 2020, 11 monthly buys in 2025 → `prefillRow` factor = 1 for all year-end shares (`german-tax-view.js:87-92`); saved record for 2025 is taxed in report year 2025 (`tax-report-builder.js:241-248`) but belongs to 2026. Test: `computeVorabpauschale` per lot and `build({year:2026})` should include 2025 records.

**B11 — Basiszins 2026 missing (High)**
`GermanTax.basiszinsFor(2026)` → `0.0253`; BMF value is **0.0320** ([BMF via Haufe, 13.01.2026](https://www.haufe.de/steuern/finanzverwaltung/18-abs-4-invstg-basiszins-zur-berechnung-der-vorabpauschale_164_481896.html)).

**B12 — Loss-pot misclassification (High)** — `tax-advisor.js:198-203`: an ETF at a loss is offered as offset for **stock** gains; a short-term crypto loss is offered against **capital income**. Neither is legal (§20 (6) S.4 EStG; §23 (3) S.7 EStG).

## 6. Security & privacy observations

- **At rest:** strong primitives (AES-256-GCM, PBKDF2-600k, random IVs), per-key encrypted IndexedDB records with encrypted manifest. The gap is coverage (§3.7): wealth history, property values, and **taxpayer name + tax ID** sit in plaintext `localStorage`, readable by any extension with storage access or a disk image. Add keys + migration; consider "encrypt everything except an explicit UI-prefs allowlist" (inverse list) so new stores are safe by default.
- **Backups:** default full backup is plaintext JSON while `backup-reminder` nudges users to create it regularly — make the encrypted export the default.
- **CSP:** no `'unsafe-inline'` scripts (good). Remaining looseness: `default-src 'self' https:` (any https frame/media), `img-src https:` (exfil beacon channel if XSS ever lands), `style-src 'unsafe-inline'`, no `frame-ancestors` (meta CSP can't set it; GitHub Pages can't send headers → clickjacking of the unlock screen is possible *(low)*). Suggest `default-src 'none'` + explicit directives.
- **Third-party links:** news `href` comes from RSS without scheme validation (`features7.js:269, 329`); React 18 still renders `javascript:` URLs (with a warning). Allow only `https:`.
- **Worker:** exact-origin CORS, allowlisted `yf` params, HMAC sync writes and server-side share allowlist are solid. Tighten `brokerproxy` (§3.9). Note that no-Origin requests (curl) are always allowed — fine for reads, but combined with the relay it removes the "only my app" property.
- **Share/MCP redaction:** verified triple validation + leak test; no issues found.
- **Audit log:** stays local as documented; ensure it never stores symbols/amounts in error messages (not audited line-by-line *(unverified)*).

## 7. Architecture & maintainability

**Core problems**
1. **Duplicated domain logic** — FIFO implemented 7×: `metrics.matchFifoLots`, `tax-report-builder.fifo`, `tax-calculation-engine.calculateRealizedGainsAdvanced`, `features4.calcFIFO`, `features7` realized/unrealized, `tax-advisor.buildCryptoLots`, `dividend-yoc`. They differ on fees, FX, corporate actions, per-category keying and tie-breaks. Two German tax engines. Bugs B1, B8, B12 all come from this.
2. **Implicit coupling via 652 `window.Maermin*` references** (338 in `renderer.js`) and ordering in `index.html`; `features1–7` are grouped by *delivery date*, not domain.
3. **Storage by convention** — every module reads/writes `localStorage` directly; encryption/sync/backup coverage depends on three hand-maintained key lists (`SENSITIVE_KEYS`, backup `KEYS`, sync snapshot) that already diverge.
4. **Data contracts are untyped** (`priceHistory` timestamp format, `currency`, `category`) — B3 is a contract bug.

**Recommendation:** keep the "no build for dev" promise by using **native ES modules** (browsers load them without a bundler); esbuild keeps producing the prod bundle.

**Incremental, low-risk migration path**
1. **Guardrails first (1–2 d):** golden-number cross-engine tests (positions vs tax lots vs advisor on the same fixture); ESLint `no-undef` with an explicit globals list; a single `KEY_REGISTRY` ({key, sensitive, backup, sync}) that `storage`, `backup-engine` and `sync-engine` read.
2. **One ledger kernel (1 sprint):** `ledger.js` → `{ openLots, disposals, cashflows }` from transactions with fees, `fxAt`, corporate actions, optional per-depot keying and tax class per asset. Re-point metrics, tax report, advisor, YoC, FIFOView, RealizedUnrealized, XIRR at it; delete the other five. Make `MaerminTaxReport` the only DE engine.
3. **ESM shell (no behaviour change):** add `src/main.js` that `import`s the existing IIFE files in the current order (side-effect imports). `index.html` loads one `<script type="module" src="src/main.js">`; `build.mjs` switches to `bundle:true` from that entry. Order is now in code, not HTML.
4. **Convert leaf modules** (pure kernels: returns, ledger, tax, fx-history, share-snapshot…) to `export` + a 1-line `window.X = api` compat shim; Node tests move to `import`. Delete the shim once `rg "window.X"` is empty.
5. **Split the app shell:** extract each `renderXView` into `views/<domain>/<View>.js`, a route table, `React.lazy` + esbuild `splitting` for heavy views. Regroup `features1–7` into `views/portfolio`, `views/tax`, `views/import`, `views/analytics`, `views/tools`.
6. **Storage facade:** `store.get/set(key)` backed by the registry; migrate direct `localStorage` calls domain by domain.
7. **Types:** `// @ts-check` + JSDoc on kernels (already planned in ROADMAP "TypeScript migration plan"), then `tsc --noEmit` in CI. Typed `PricePoint { t: ISO8601; p: number; cur: string }` prevents B3-class bugs.

Each step ships independently and keeps `npm test` green; steps 1–2 deliver most of the correctness value.
